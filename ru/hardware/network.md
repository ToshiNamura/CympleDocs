# Настройка сети

Камеры Cymple — крошечные веб-серверы. Если консоль не может сделать `GET` изображения по
`http://<ip>/`, вы получаете *Waiting for image*, и больше ничего не работает. Эта страница один раз
решает весь класс таких проблем.

## Как камера попадает в сеть

```text
camera boots → reads stored SSID/password → joins Wi-Fi → gets IP (DHCP or static)
             → starts MJPEG server → waits for the console to pull frames
```

Значит, должны выполняться два условия:

1. Камера находится в Wi-Fi-сети, **доступной ПК**.
2. Камера сохраняет **один и тот же IP** между перезагрузками, потому что консоль хранит IP, а не имя
   хоста.

## Шаг 1 — Настройте учётные данные Wi-Fi

В зависимости от сборки прошивки учётные данные задаются либо через captive portal, либо в инструменте
прошивки:

- **Сборки с captive portal:** подключитесь к точке доступа самой камеры (SSID обычно начинается с
  `Cymple` или с названия платы), откройте страницу настройки, введите SSID и пароль, сохраните —
  устройство перезагрузится в режим клиента.
- **Сборки с записью при прошивке:** SSID и пароль записываются вместе с прошивкой в инструменте
  прошивки. Чтобы их изменить, перепрошейте устройство.

После перезагрузки камеры должны появиться в списке клиентов вашего роутера.

## Шаг 2 — Сделайте IP постоянным

| Способ | Как | Примечания |
|---|---|---|
| **Резервирование DHCP** (рекомендуется) | Привяжите MAC-адрес камеры к фиксированной аренде в роутере | Переживает обновления прошивки, настройка устройства не нужна |
| **Статический IP в устройстве** | Задайте адрес, маску и шлюз на камере | Должен совпадать с вашей подсетью; опечатка означает перепрошивку |
| **Имя хоста** | Не используется | Консоль ждёт буквальный IP |

Выбирайте адреса вне динамического пула роутера, чтобы избежать конфликтов, например
`192.168.1.201–210`.

## Шаг 3 — Проверьте с ПК

```powershell
# 1. Is the host up?
Test-Connection 192.168.1.201

# 2. Is the MJPEG endpoint answering?
curl.exe -I http://192.168.1.201/

# 3. Is the port open?
Test-NetConnection 192.168.1.201 -Port 80
```

| Результат | Значение |
|---|---|
| Пинг не проходит | Неверный IP, другая подсеть или не удалось подключиться к Wi-Fi |
| Пинг проходит, HTTP — нет | Камера в сети, но сервер потока не запущен — перепрошейте |
| Работает и то и другое, а консоль всё равно показывает *Waiting for image* | Windows Firewall блокирует консоль или консоль работает в другом сетевом профиле |

## Шаг 4 — Межсетевой экран Windows

Консоли нужно разрешить исходящие подключения и приём ответов в частных сетях:

1. **Windows Security → Firewall & network protection → Allow an app through firewall**.
2. Добавьте `Cymple.exe` (или запись установщика) и отметьте **Private**.
3. Если вы используете второй сетевой адаптер (отдельный Wi-Fi-донгл для VR), установите для этой
   сети профиль **Private**, а не Public: Public применяет гораздо более строгий набор правил.

## Шаг 5 — Гигиена роутера

| Настройка | Требуемое состояние | Почему |
|---|---|---|
| Изоляция AP / клиентов | **Выключено** | Иначе ПК вообще не достанет камеру |
| Band steering | Выключено или раздельные SSID | Удерживает камеры на 5 ГГц осознанно |
| IGMP snooping / фильтрация multicast | По умолчанию (не включайте) | В некоторых сборках ломает обнаружение |
| QoS / airtime fairness | Необязательно | Помогает удержать стабильный `FPS`, когда поток передают другие устройства |

> **Правило большого пальца.** Если VRChat работает плавно, а `FPS` в предпросмотрах держится на
> 8–12, проблема в Wi-Fi-канале, а не в процессоре. Переставьте роутер, разделите диапазоны или
> уменьшите число устройств в SSID на 2,4 ГГц.

## Бюджет пропускной способности

Каждая камера передаёт MJPEG. Грубая оценка при 640×480 / 25 FPS — 2–6 Мбит/с на камеру в зависимости
от сложности сцены. Полной конфигурации из четырёх камер (2 для глаз + 2 для рта) нужно, таким
образом, стабильные 20 Мбит/с эфирного времени — незаметно на 5 ГГц и на пределе на загруженном
канале 2,4 ГГц.

## Несколько трекеров на одном ПК

Консоль адресует устройства по IP, поэтому годится любая комбинация:

- айтрекер на `192.168.1.201` / `.202`
- трекер рта на `192.168.1.203`
- второй комплект трекеров для второго пользователя на `.211` / `.212`

Только один экземпляр консоли может занять OSC-порты (9000/9001/9002) на машине, поэтому двум
пользователям нужны два ПК.
