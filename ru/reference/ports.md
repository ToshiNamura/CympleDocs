# Порты и адреса

## Порты на ПК

| Порт | Протокол | Направление | Владелец | Назначение | Настраивается |
|---|---|---|---|---|---|
| `9000` | UDP (OSC) | Cymple → VRChat | VRChat | Вход параметров аватара | Да — **Send** на [VRCFT](../software/vrcft.md), **VRCHat target → Port** в [OSC Router](../software/osc-router.md) |
| `9001` | UDP (OSC) | VRChat → Cymple | Cymple | Выход параметров VRChat | Да — **Receive** на [VRCFT](../software/vrcft.md) |
| `9002` | UDP (OSC) | Устройство/приложение → Cymple | Cymple | Данные от сторонних приложений, пересылаются на `9000` | Да — **Device input port** в [OSC Router](../software/osc-router.md) |
| `22999` | UDP | Cymple → модуль VRCFT | Cymple | Поток пакетов совместимости (70 полей), используется при выключенном **VRC Direct** | Нет |
| ephemeral | UDP | Цели пересылки в консоль | целевое приложение | Всё, что вы добавили в [OSC Router](../software/osc-router.md) | Для каждой цели |

> Соответствие выбрано осознанно: заводские настройки VRChat — **приём 9000 / отправка 9001**,
> поэтому Cymple использует их без изменений. Если вы меняете настройки VRChat, зеркально поменяйте
> их и здесь.

## Адреса камер

Каждая камера на ESP32 — маленький HTTP-сервер.

| Адрес | Протокол | Порт | Назначение |
|---|---|---|---|
| `/` | HTTP | `80` | Стартовая страница / статус |
| MJPEG-поток | HTTP | `80` (multipart) | Кадры, которые забирает консоль |
| Страница настройки | HTTP | `80` | Настройка в стиле captive portal в некоторых сборках |

Консоль обращается к камерам только по IP; протокола обнаружения нет. См.
[Настройка сети](../hardware/network.md).

## Кто может занять порт

| Правило | Причина |
|---|---|
| Только один процесс может занять `9000`, `9001` или `9002` | Две консоли или консоль плюс другое OSC-приложение на тех же портах — и одно из них молча остаётся без данных |
| Пока роутер включён, портом `9001` владеет Cymple | Другие приложения должны получать данные VRChat через **цель пересылки**, а не занимая `9001` сами |
| Внешний VRCFaceTracking не должен конкурировать с VRC Direct | Используйте один путь; прямой режим плюс внешний модуль дают конфликтующие записи |

## Проверка порта в Windows

```powershell
# Who is listening?
Get-NetUDPEndpoint -LocalPort 9000,9001,9002 | Select-Object LocalAddress,LocalPort,OwningProcess

# What is that process?
Get-Process -Id <PID>

# Is anything arriving? (quick counter check)
Get-NetUDPEndpoint | Where-Object LocalPort -in 9000,9001,9002
```

## Правила брандмауэра, которые действительно нужны

| Направление | Правило |
|---|---|
| Исходящие на IP камер | Разрешить консоль в сетях **Private** |
| Входящие `9001`, `9002` | Разрешить только в **Private** — никогда не открывайте OSC-порты в публичную сеть |
| `Allow LAN devices` включён | Только в доверенной локальной сети; он открывает `9002` для других хостов |

## Смена портов: безопасный порядок

1. Остановите VRChat.
2. Поменяйте порты консоли ([VRCFT](../software/vrcft.md)).
3. Поменяйте порты VRChat так же или добавьте параметр запуска
   `--osc=<vrchat-in>:<target-ip>:<vrchat-out>`.
4. Перезапустите VRChat и проверьте **Input Rate** / **Output Rate** на [VRCFT](../software/vrcft.md).
5. И только после этого трогайте цели в [OSC Router](../software/osc-router.md).
