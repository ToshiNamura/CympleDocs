# Внешний VRCFT

Иногда консоль не должна быть последним звеном. Если вы смешиваете трекеры, хотите единый набор
параметров VRCFaceTracking или нуждаетесь в его инструментах для аватаров, запустите модуль Cymple
*внутри* VRCFT и отдайте подключение к VRChat самому VRCFT.

## Когда выбирать этот путь

| Ситуация | Путь |
|---|---|
| Только Cymple, простой аватар | [VRC Direct](../software/vrcft.md) — меньше движущихся частей |
| Cymple + другой трекер | Внешний VRCFT — один интегратор на оба |
| Аватар уже настроен под VRCFT | Внешний VRCFT — ничего не нужно переделывать |
| Отладка проблемы на уровне модуля | Внешний VRCFT — помогает собственный журнал VRCFT |

## Что понадобится

- Установленный VRCFaceTracking ([vrcft.io](https://vrcft.io)).
- ZIP-архив релиза `CympleFaceTracking` (DLL + метаданные модуля). Среду Core предоставляет сам
  VRCFaceTracking.
- Консоль, запущенная с выключенным **VRC Direct**.

## Установка модуля

1. Откройте VRCFaceTracking → **Module Manager**.
2. Выберите **Install from file** (установка модуля из файла).
3. Укажите ZIP из релиза.
4. Перезапустите VRCFaceTracking.
5. Убедитесь, что модуль есть в списке и включён.

## Настройка консоли

1. [VRCFT](../software/vrcft.md) → выключите **VRC Direct**.
2. Оставьте порты `9001` / `127.0.0.1` / `9000`, если только VRChat не настраивали вручную.
3. Следите за **Input Rate** — значение должно оставаться ненулевым, потому что VRCFT продолжает
   обмениваться данными с VRChat.

Почему прямой режим должен быть выключен: поток пакетов совместимости (UDP-пакет из 70 полей на порт
`22999`) консоль отправляет только при отключённом прямом режиме. При включённом прямом режиме
модулю нечего читать, и он сообщает об отсутствии данных.

## Детали поведения

| Аспект | Поведение |
|---|---|
| Доступность глаз и мимики | Определяется аргументами `Initialize(eyeAvailable, expressionAvailable)` в VRCFT, а не аппаратными переключателями консоли |
| Аппаратные переключатели консоли | `cymple_eye_sw` / `cymple_mouth_sw` не могут отключить вход *другого* приложения — модуль намеренно их игнорирует |
| Смена доменов | Применяется, когда VRCFT переинициализирует модуль |
| Флаги пакета | Показывают, какие домены реально несут данные |
| Поведение при обрыве | Примерно через 1 с без данных вывод следует `[Cymple_Mouth] reset_expression_on_tracking_disconnect` (по умолчанию сброс; `false` — удерживать последний кадр) |
| Откуда читается эта настройка | `%LOCALAPPDATA%\Cymple\iniFile.ini`, с устаревшим запасным путём `C:\Cymple\iniFile.ini`; перечитывается раз в секунду |
| Взгляд и выражения | Передаются обработанные значения Cymple; мёртвая зона для глаз применяется в консоли |
| Расширение зрачка | Передаётся в диапазоне `0–1` |

### Известное ограничение

Текущий отправитель Cymple может продолжать передавать последний отсчёт мимики после отключения
устройства. В формате пакета нет признака свежести данных для устройства мимики, поэтому модуль
замечает остановку потока, но не может по повторяющимся одинаковым отсчётам понять, что устройство
отключилось. Если мимика замирает вместо сброса, причина именно в этом — включите **Reset expression
after disconnect** и почините канал связи с устройством.

## Проверка

1. VRCFT показывает модуль Cymple загруженным и включённым.
2. Собственный просмотр параметров в VRCFT показывает меняющиеся значения глаз и выражений.
3. Консоль показывает ненулевой **Output Rate**? Нет, не показывает — прямой режим выключен, консоль
   отправляет только поток совместимости. Судите по стороне VRCFT.
4. Аватар в VRChat реагирует.

## Возврат назад

Снова включите **VRC Direct** и отключите внешний модуль. Активным должен быть только один путь;
если работают оба, получаются дублирующиеся и конфликтующие записи параметров.
